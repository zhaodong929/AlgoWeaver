**审计日期：** 2026-11-06（Asia/Shanghai）

## 1. 审计结论

当前仓库是一个可读、可测试的 v0.1.0 垂直切片，已实现“文本输入 → Mock/可选 LiteLLM → Pydantic 能力卡片 → 证据绑定”的核心逻辑。当前工作区没有发现 `.git` 目录，因此无法核验提交历史、分支或远程；根目录下也没有 `uv` 可执行文件。项目声明支持 Python 3.12–3.13，但本次实际解释器为 Python 3.13.9。

在设置 `PYTHONPATH=src` 后，测试结果为 **10 passed, 2 skipped**。两个跳过项是 LangGraph 集成测试，原因是当前环境没有安装 `langgraph`。未设置 `PYTHONPATH` 时，pytest 在加载 `tests/conftest.py` 阶段即因源码包未安装而失败（`ModuleNotFoundError: algo_weaver`）。这说明“从源码目录直接运行”缺少安装步骤或本地开发引导。

核心 CLI 的 `version` 命令可在源码路径下运行；`extract` 命令依赖 LangGraph，因此当前环境中不能完成端到端 CLI 抽取。LiteLLM 适配器有实现和单元测试，但当前环境没有可确认的真实 provider 调用证据，不能把它标记为已验证的在线能力。

## 3. 已实现功能

### 3.1 领域模型与证据

- `src/algo_weaver/schemas/capability.py` 使用 Pydantic 定义 `AlgorithmDraft`、`AlgorithmCapability`、`EvidenceRef`、参数和来源类型。
- 模型响应先经过 `AlgorithmDraft.model_validate_json` 校验，再由应用附加实际输入的 `EvidenceRef`。
- Mock 或不完整字段会将卡片保持为 `needs_review` 或 `draft`；代码中没有把模型猜测直接提升为 `verified` 的路径。

### 3.2 LLM 接口

- `llm/base.py` 提供 provider-neutral 的 `ChatModel` 协议。
- `llm/mock.py` 提供确定性离线模型，用于开发和测试；输出明确包含待确认信息。
- `llm/litellm_adapter.py` 支持 LiteLLM 统一 completion 接口、API key/base/temperature/timeout 配置，以及从 Markdown 代码围栏或包裹文本中提取 JSON。
- `llm/factory.py` 按配置选择 Mock 或 LiteLLM。

### 3.3 抽取服务与图

- `services/capability_extractor.py` 实现输入非空、长度上限、结构化 Prompt、JSON 校验、来源证据绑定。
- `agents/extraction_graph.py` 定义一个 LangGraph 节点 `extract_capability`，并将异常转化为可读错误。
- 图结构目前只有一条路径，没有持久化 checkpoint、条件路由、循环修复、人工介入或流式事件。

### 3.4 CLI 与测试

- `cli.py` 提供 `version` 和 `extract` 命令；抽取命令可读取 UTF-8 文本/Markdown，写出 JSON 能力卡片。
- 测试覆盖 Schema、Mock 抽取、输入边界、Prompt 注入文本作为数据、LiteLLM JSON 提取和 CLI version。

## 6. 代码质量与架构观察

### 优点

- 核心服务与 CLI、模型适配器、Schema 已经分层，后续可在服务层增加 ingestion/retrieval/verification，而无需把逻辑塞入 CLI。
- `ChatModel` 协议隔离了 provider，Mock 测试无需网络。
- 证据由应用根据真实输入生成，避免模型伪造来源。
- 配置使用 `pydantic-settings`，API key 通过 `SecretStr` 保存。
- 输入长度上限和有限字段校验已存在，适合作为后续工作流的基础节点。

### 主要问题

- 项目没有可用的 Git 元数据，无法按用户要求创建 feature 分支、保留历史或安全推送；需先确认 GitHub 仓库与本地目录关系。
- `uv.lock` 不存在，依赖版本不可复现；当前机器也没有 `uv`。
- `tests/test_extraction_graph.py` 通过 `importorskip` 隐藏了核心图功能未安装的问题；不能把“10 passed”解读为全量功能通过。
- CLI `extract` 依赖 LangGraph，但 README 的安装/测试步骤在未安装依赖时会失败；当前运行方式依赖 `PYTHONPATH=src` 或先安装项目。
- `mypy` 类型错误需要修复或配置第三方包忽略规则。
- 现有 `data/` 目录没有看到实际处理产物；示例 JSON 是静态样例，不能作为运行结果证据。
- 没有独立 ingestion、retrieval、execution、verification、persistence 模块，当前仍属于第一条垂直切片。

## 7. 依赖与兼容性判断

`pyproject.toml` 的核心依赖范围为 LangGraph 1.x、Pydantic 2.x、pydantic-settings 2.x、LiteLLM 1.x、Typer 0.x、Rich 13/14；optional extras 预留 Docling、Tree-sitter、Qdrant、FastAPI、Langfuse、Docker、Hypothesis 等。声明本身没有发现直接冲突，但没有 `uv.lock` 和完整安装环境，无法验证组合解析结果。下一步应在可用的 uv 或等价隔离环境中生成锁文件并重新跑完整测试。
