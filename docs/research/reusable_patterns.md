# 可复用设计模式

## 1. 证据驱动的反思

反思输入必须包含独立验证器产生的证据：失败测试、traceback、静态检查、性能回归或检索缺口。反思输出是可执行修复计划，不能只输出“看起来正确”。

## 2. 计划 + 动态执行

先生成高层算法复刻计划，随后每个子步骤使用 ReAct 工具循环。计划只约束目标和依赖，条件路由允许根据证据跳过、重试或重规划。

## 3. 状态与产物分离

短期线程状态保存当前任务和检查点；长期能力库保存版本化能力卡片、代码、依赖、实验与报告。两者通过能力 ID 和证据 ID 关联。

## 4. 受限 ACI

使用有限的 `read/search/patch/test` 工具替代通用 shell。工具输出结构化、分页、可截断；编辑先做语法检查；所有路径解析后必须位于工作区根目录内。

## 5. 可恢复副作用

写文件、安装依赖、运行测试、写数据库都是副作用。为每个副作用记录幂等键、输入哈希、退出码和产物路径；恢复时跳过已经成功的任务。

## 6. 渐进式检索

先通过元数据和稀疏匹配缩小候选，再做 dense retrieval 和 rerank。按函数/标题/表格边界切分，返回来源路径、页码/行号和证据级别。

## 7. 状态门禁

`Pending -> Validating -> Verified` 只能由独立验证器推进；失败回到 `Failed`，信息不足保持 `Pending`。LLM 推断不能覆盖原始证据。

## 8. 预算与终止

每个任务设置最大步骤数、最大修复轮数、超时、输出大小和资源配额。超过预算后保存完整轨迹并明确报告失败原因。
